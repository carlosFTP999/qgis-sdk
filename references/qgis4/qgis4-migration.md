# QGIS 4 and PyQt6 Migration

Default target: QGIS 4.x with PyQt6. Confirm the project target before applying
version-specific advice. QGIS 3.x plugins that use PyQt5 must not be copied
unchanged into a QGIS 4 plugin.

## Verify the runtime first

```python
from qgis.core import Qgis

print(Qgis.QGIS_VERSION)
print(Qgis.QGIS_VERSION_INT)
```

Run this with the Python interpreter bundled with QGIS, not with the system
Python. The static validator never proves that a plugin imports or runs inside
QGIS.

## Metadata for QGIS 4

The metadata contract changed with QGIS 4:

- `category` is one of `Raster`, `Vector`, `Database`, `Mesh`, `Web`, or omitted
  for the default Plugins menu. `category=Plugins` is not a documented value.
- `supportsQt6` was removed from QGIS core and is no longer recognized. Remove
  it instead of setting it to a false-looking value.
- A QGIS 4-only plugin sets `qgisMinimumVersion=4.0`. `qgisMaximumVersion` is
  optional; omit it unless you deliberately cap the supported range.
- `hasProcessingProvider=yes` only when the plugin actually registers a
  Processing provider.
- `plugin_dependencies` is optional. Its comma-separated values are QGIS plugin
  metadata `name` values, not pip distribution names. The official example
  shows an optional `==version`, and the key exists since QGIS 3.8; do not
  require a specific operator.
- A publishable plugin ships the full canonical text of a GPLv2-or-later
  compatible license in `LICENSE`; any metadata license fields must match.

See `plugin-structure.md` for the full `metadata.txt` example.

## Imports

Use the QGIS Qt shim:

```python
from qgis.PyQt.QtCore import QMetaType, Qt
from qgis.PyQt.QtGui import QAction, QIcon
from qgis.PyQt.QtWidgets import QDialog, QVBoxLayout
```

Do not import `PyQt5`, `PyQt6`, `PySide2`, or `PySide6` directly. The shim
keeps the plugin aligned with the QGIS build and avoids loading a second Qt
binding. QGIS 4 bindings use SIP and PyQt6, and official examples import through
`qgis.PyQt`. Official QGIS migration guidance allows replacing PyQt5 imports
with PyQt6 but recommends the `qgis.PyQt` shim; the stricter direct-PySide
rejection here is harness policy, not an official QGIS prohibition.

## Scoped enums

PyQt6 removed many unscoped enum aliases. Use the enum type explicitly.

| Wrong | Correct |
|---|---|
| `Qgis.Info` | `Qgis.MessageLevel.Info` |
| `Qgis.Warning` | `Qgis.MessageLevel.Warning` |
| `Qt.Checked` | `Qt.CheckState.Checked` |
| `Qt.AlignLeft` | `Qt.AlignmentFlag.AlignLeft` |
| `QgsWkbTypes.Point` | `QgsWkbTypes.Type.Point` |
| `QgsWkbTypes.PolygonGeometry` | `Qgis.GeometryType.Polygon` |
| `QgsFeatureSink.FastInsert` | `QgsFeatureSink.Flag.FastInsert` |
| `QgsProcessingAlgorithm.FlagHideFromToolbox` | `QgsProcessingAlgorithm.Flag.FlagHideFromToolbox` |

`QgsWkbTypes.Type` is the scoped WKB-type enum; `Qgis.GeometryType` (also
exposed as `QgsWkbTypes.GeometryType`) groups WKB types into point, line, and
polygon. Scoped `GeometryType` members are `Point`, `Line`, `Polygon`, `Unknown`,
and `Null`; `*Geometry` names are old
unscoped compatibility aliases, not scoped members. `QgsGeometry.type()` returns
a geometry-group value, so compare it with `Qgis.GeometryType.Point`, not with a
WKB value. When an enum is not obvious, inspect the QGIS 4 API instead of
guessing.

## Field types

Use `QMetaType` for new vector fields:

```python
from qgis.PyQt.QtCore import QMetaType
from qgis.core import QgsField

field = QgsField("area_m2", QMetaType.Type.Double)
```

`QVariant` field types are legacy and are removed or deprecated in modern
QGIS. Do not introduce them in new code.

## Removed or renamed APIs

Common migration points:

- `QgsMapLayerRegistry` -> `QgsProject.instance()`.
- `QDesktopWidget` -> `QGuiApplication.screens()` or `QScreen`.
- `QRegExp` -> `QRegularExpression`.
- `exec_()` -> `exec()`.
- `QAction` lives in `qgis.PyQt.QtGui`, not `QtWidgets`.
- `QgsGeometry.fromPolyline` is a legacy compatibility alias; use the current
  `QgsGeometry` constructors or `fromPolylineXY` where appropriate.
- `QgsCoordinateReferenceSystem.createFromString` is a legacy compatibility
  alias; use the current `QgsCoordinateReferenceSystem` constructors or
  `QgsCoordinateReferenceSystem.fromEpsgId`.
- `QgsProcessingAlgorithm.Flag*` -> `QgsProcessingAlgorithm.Flag.Flag*`.

Verify each symbol against the installed QGIS API before changing a working
plugin.

## Resource and icon changes

`pyrcc`-compiled resources are legacy for the Qt 5 toolchain. Prefer files
loaded with `QIcon` from a plugin-relative path, or a Qt resource generated by
the current Qt 6 resource toolchain when the project requires it.

```python
import os
from qgis.PyQt.QtGui import QIcon

icon = QIcon(os.path.join(os.path.dirname(__file__), "icon.png"))
```

Keep the icon inside the plugin directory and declare it in `metadata.txt` when
the plugin uses one.

## Processing migration

- Register providers through `QgsApplication.processingRegistry()`.
- Remove the provider in `unload()`.
- Use scoped flags.
- Use `QgsProcessingParameterFeatureSink` and `QgsFeatureSink.Flag.FastInsert`.
- Keep `processAlgorithm` free of GUI calls.

## Migration checklist

- [ ] Imports use `qgis.PyQt.*`.
- [ ] Enums are scoped.
- [ ] Field types use `QMetaType`.
- [ ] `metadata.txt` uses a documented `category` or omits it, and has no `supportsQt6`.
- [ ] A QGIS 4-only plugin uses `qgisMinimumVersion=4.0`; any maximum is deliberate.
- [ ] `LICENSE` holds the full canonical license text.
- [ ] No removed API remains.
- [ ] Icons and resources load without legacy `pyrcc` resources; use the Qt 6
      resource toolchain or a `QIcon` from a plugin-relative path.
- [ ] `initGui()` and `unload()` are symmetric.
- [ ] The plugin was imported with the QGIS Python interpreter.
- [ ] A real runtime test was performed or the limitation was reported.
